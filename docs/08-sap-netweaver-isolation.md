# SAP NetWeaver 平台隔离机制分析

## 概述

本文档分析 SAP NetWeaver 平台如何实现**技术底座组件开发**与**业务应用开发**之间的隔离。这种隔离是 SAP 系统能够支持持续升级、客户化定制和合作伙伴扩展的核心机制。

```
│  │  Y           │  Partner       │  合作伙伴开发对象                   ││

│                                                                         │
│  对象命名规范                                                           │

└─────────────────────────────────────────────────────────────────────────┘
```

#### 命名空间保护机制

```abap
" SAP 系统通过命名空间检查保护标准对象
" 示例: 尝试修改 SAP 标准对象时会触发保护检查

" 受保护的对象检查
IF object_name CP '/SAP/*' OR object_name CP 'SAP*'.
  " SAP 标准对象
  IF modification_assistant_enabled = 'X'.
    " 只有通过 Modification Assistant 才能修改
    " 并且需要修改钥匙 (Modification Key)
    CALL FUNCTION 'MODIFICATION_CHECK'
      EXPORTING
        object_name = object_name
      EXCEPTIONS
        no_modification_key = 1
        system_object_protected = 2.
  ENDIF.
ENDIF.

" 客户开发对象命名检查
IF object_name CP 'Z*' OR object_name CP 'Y*'.
  " 允许客户开发
  " 无需修改钥匙
ENDIF.
```

## 四、增强框架 (Enhancement Framework) 隔离

### 4.1 增强类型与隔离等级

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    增强框架隔离等级                                      │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  隔离等级金字塔 (从低到高):                                              │
│                                                                         │
│           ┌─────────────────┐                                           │
│           │  Modifications   │  ← 最低隔离 (直接修改 SAP 代码)           │
│           │  (不推荐)        │      - 需要修改钥匙                       │
│           ├─────────────────┤      - 升级时可能冲突                     │
│           │  BAdIs           │  ← 推荐方式                              │
│           │  (业务增强)      │      - 面向对象                          │
│           ├─────────────────┤      - 多重实现                          │
│           │  Enhancement     │  ← 标准增强                              │
│           │  Spots          │      - 显式扩展点                         │
│           ├─────────────────┤                                          │
│           │  Implicit        │  ← 隐式增强                              │
│           │  Enhancements    │      - 子屏幕出口                        │
│           └─────────────────┘                                          │
│                                                                         │
│  BAdI (Business Add-In) 隔离机制:                                       │
│  ┌────────────────────────────────────────────────────────────────────┐ │
│  │  技术特性:                                                         │ │
│  │  - 面向对象接口                                                    │ │
│  │  - 运行时动态调用                                                  │ │
│  │  - 支持多重实现 (Multiple Use)                                      │ │
│  │  - 支持筛选器 (Filter)                                              │ │
│  │  - 可以定义自己的 BAdI                                             │ │
│  │                                                                    │ │
│  │  BAdI 调用流程:                                                     │ │
│  │  ┌────────────┐    ┌────────────┐    ┌────────────┐               │ │
```

### 4.2 BAdI 实现示例

```abap
" ========== SAP 标准代码 (受保护) ==========
" SAP 定义的标准 BAdI 接口
DEFINE INTERFACE if_ex_invoice_badi
  PUBLIC .

  METHODS:
    calculate_discount
      IMPORTING
        iv_amount        TYPE /sapp/invoice_amount
        iv_customer      TYPE /sapp/customer_id
      RETURNING
        VALUE(rv_discount) TYPE /sapp/discount_amount
      RAISING
        cx_invoice_exception.

    validate_invoice
      IMPORTING
        is_invoice       TYPE /sapp/invoice_struc
      RETURNING
        VALUE(rv_valid)  TYPE abap_bool
      RAISING
        cx_invoice_exception.

ENDINTERFACE.

" SAP 标准程序调用 BAdI
REPORT /sapp/invoice_process.

DATA: lo_badi TYPE REF TO if_ex_invoice_badi.

" 获取 BAdI 实现 (动态调用)
lo_badi = GET BADI if_ex_invoice_badi
  FILTERS
    company_code = '1000'
    invoice_type = 'FR'.

" 调用 BAdI 方法 (调用客户实现)
TRY.
    rv_discount = lo_badi->calculate_discount(
      iv_amount   = lv_amount
      iv_customer = lv_customer
    ).

    " 如果没有实现，使用默认逻辑
    CATCH cx_badi_not_implemented.
      rv_discount = lv_amount * '0.05'.  " 默认 5% 折扣
ENDTRY.

" ========== 客户实现 (隔离) ==========
" 客户在自己的命名空间实现 BAdI
CLASS zcl_invoice_badi_impl DEFINITION
  PUBLIC
  FINAL
  CREATE PUBLIC .

  PUBLIC SECTION.
    INTERFACES: if_ex_invoice_badi.

    ALIASES:
      calculate_discount FOR if_ex_invoice_badi~calculate_discount,
      validate_invoice   FOR if_ex_invoice_badi~validate_invoice.

ENDCLASS.

CLASS zcl_invoice_badi_impl IMPLEMENTATION.

  METHOD calculate_discount.
    " 客户特定逻辑 - 与 SAP 标准代码完全隔离
    DATA: lv_customer_type TYPE char1.

    " 查询客户等级
    SELECT SINGLE customer_type
      INTO lv_customer_type
      FROM zcustomer_level
      WHERE customer_id = iv_customer.

    " 根据等级计算折扣
    CASE lv_customer_type.
      WHEN 'A'.
        rv_discount = iv_amount * '0.15'.  " A 级 15%
      WHEN 'B'.
        rv_discount = iv_amount * '0.10'.  " B 级 10%
      WHEN OTHERS.
        rv_discount = iv_amount * '0.05'.  " 其他 5%
    ENDCASE.

  ENDMETHOD.

  METHOD validate_invoice.
    " 客户特定校验逻辑
    IF is_invoice-amount < 0.
      RAISE EXCEPTION TYPE cx_invoice_exception
        EXPORTING
          textid = cx_invoice_exception=>negative_amount.
    ENDIF.

    rv_valid = abap_true.
  ENDMETHOD.

ENDCLASS.

" ========== BAdI 实现 (SE19) ==========
" 客户通过 SE19 事务注册 BAdI 实现
" - BAdI 定义: INVOICE_BADI
" - 实现类: ZCL_INVOICE_BADI_IMPL
" - 筛选条件: company_code = '1000', invoice_type = 'FR'
" - 状态: 活跃
```

```java
// ========== 平台层 - 认证模块示例 ==========
package com.nexterp.platform.auth.api;

import java.util.Map;
import java.util.Set;

/**
 * 平台层认证服务接口
 * 这是技术底座提供的核心接口，业务层依赖此接口
 *
 * @version 1.0.0
 * @since 1.0.0
 * @apiNote 接口版本必须通过 @since 标注，便于兼容性管理
 */
public interface AuthService {

    /**
     * 认证用户
     *
     * @param username 用户名
     * @param password 密码
     * @param tenantId 租户ID
     * @return 认证令牌信息
     * @throws AuthenticationException 认证失败
     */
    TokenInfo authenticate(String username, String password, Long tenantId)
        throws AuthenticationException;

    /**
     * 验证令牌
     *
     * @param token 令牌
     * @return 用户信息
     * @throws InvalidTokenException 令牌无效
     */
    UserInfo verifyToken(String token) throws InvalidTokenException;

    /**
     * 检查权限
     *
     * @param userId 用户ID
     * @param permission 权限码
     * @return 是否有权限
     */
    boolean hasPermission(Long userId, String permission);

    /**
     * 获取用户所有权限
     *
     * @param userId 用户ID
     * @return 权限集合
     */
    Set<String> getUserPermissions(Long userId);

    /**
     * 令牌信息
     */
    record TokenInfo(
        String accessToken,
        String refreshToken,
        Long expiresIn,
        Map<String, Object> additionalInfo
    ) {}

    /**
     * 用户信息
     */
    record UserInfo(
        Long userId,
        String username,
        String displayName,
        Long tenantId,
        Set<String> roles,
        Set<String> permissions
    ) {}
}

package com.nexterp.business.finance.internal;

import com.nexterp.platform.auth.api.AuthService;
import com.nexterp.platform.auth.api.UserInfo;
import com.nexterp.platform.auth.api.InvalidTokenException;

/**
 * 财务模块服务实现
 * 依赖平台层提供的认证服务
 *
 * 通过接口依赖实现隔离，业务模块不依赖平台实现细节
 */
@Service
@RequiredArgsConstructor
public class FiVoucherServiceImpl implements FiVoucherService {

    /**
     * 依赖平台层认证服务接口
     * 实际注入由平台层提供
     */
    private final AuthService authService;

    /**
     * 财务凭证仓储
     * 业务层内部实现
     */
    private final FiVoucherRepository voucherRepository;

    @Override
    public FiVoucherVO getById(Long id, String token) {
        // 1. 使用平台层认证服务验证令牌
        UserInfo userInfo;
        try {
            userInfo = authService.verifyToken(token);
        } catch (InvalidTokenException e) {
            throw new BusinessException("令牌无效", e);
        }

        // 2. 检查权限
        if (!authService.hasPermission(userInfo.userId(), "finance:voucher:view")) {
            throw new ForbiddenException("无权访问财务凭证");
        }

        // 3. 业务逻辑
        FiVoucher voucher = voucherRepository.findById(id)
            .orElseThrow(() -> new NotFoundException("凭证不存在"));

        // 4. 租户隔离检查
        if (!voucher.getTenantId().equals(userInfo.tenantId())) {
            throw new ForbiddenException("无权访问其他租户数据");
        }

        return toVO(voucher);
    }

    @Override
    @Transactional
    public Long create(FiVoucherCreateDTO dto, String token) {
        // 类似的认证和权限检查
        UserInfo userInfo = authService.verifyToken(token);

        // 业务逻辑...
        FiVoucher voucher = buildVoucher(dto, userInfo);
        return voucherRepository.save(voucher).getId();
    }
}
```

```java
import java.util.List;

/**
 * 服务提供者接口
 * 类似 SAP 的 BAdI 接口

 */
public interface VoucherExtensionSPI {

    /**
     * 凭证创建前验证
     *
     * @param dto 凭证创建 DTO
     * @throws ValidationException 验证失败
     */
    default void preValidate(FiVoucherCreateDTO dto) throws ValidationException {
        // 默认实现: 不做任何验证
    }

    /**
     * 凭证创建后处理
     *
     * @param voucherId 凭证ID
     * @param dto 凭证创建 DTO
     */
    default void postCreate(Long voucherId, FiVoucherCreateDTO dto) {
        // 默认实现: 不做任何处理
    }

    /**
     * 凭证金额计算扩展
     *
     * @param originalAmount 原始金额
     * @param dto 凭证创建 DTO
     * @return 计算后的金额
     */
    default BigDecimal calculateAmount(BigDecimal originalAmount, FiVoucherCreateDTO dto) {
        // 默认实现: 返回原始金额
        return originalAmount;
    }

    /**
     * 获取 SPI 实现优先级
     *
     * @return 优先级，数字越大优先级越高
     */

// ========== SPI 加载器 (平台层) ==========
package com.nexterp.platform.extension.loader;

import java.util.List;
import java.util.Comparator;

/**
 * SPI 加载器
 * 使用 Java ServiceLoader 机制加载扩展实现
 */
@Component
@RequiredArgsConstructor
public class VoucherExtensionLoader {

    private final List<VoucherExtensionSPI> extensions;

    /**
     * 构造函数注入所有 SPI 实现
     * Spring 自动扫描并注入所有 VoucherExtensionSPI 的实现类
     */
    public VoucherExtensionLoader(List<VoucherExtensionSPI> extensions) {
        // 按优先级排序
        this.extensions = extensions.stream()
            .sorted(Comparator.comparingInt(VoucherExtensionSPI::getPriority).reversed())
            .toList();
    }

    /**
     * 执行前置验证
     * 按优先级依次执行所有实现的 preValidate 方法
     */
    public void executePreValidate(FiVoucherCreateDTO dto) throws ValidationException {
        for (VoucherExtensionSPI extension : extensions) {
            extension.preValidate(dto);
        }
    }

    /**
     * 执行后置处理
     * 按优先级倒序依次执行所有实现的 postCreate 方法
     */
    public void executePostCreate(Long voucherId, FiVoucherCreateDTO dto) {
        for (VoucherExtensionSPI extension : extensions) {
            extension.postCreate(voucherId, dto);
        }
    }

    /**
     * 计算金额
     * 按优先级依次执行，每个实现都可以修改金额
     */
    public BigDecimal executeCalculateAmount(BigDecimal originalAmount, FiVoucherCreateDTO dto) {
        BigDecimal result = originalAmount;
        for (VoucherExtensionSPI extension : extensions) {
            result = extension.calculateAmount(result, dto);
        }
        return result;
    }
}
```

### 8.1 SAP NetWeaver 隔离机制总结

| 隔离维度 | SAP 机制 | 隔离效果 |
|---------|---------|---------|
| **软件组件** | SCM (SAP_BASIS, SAP_ABA, SAP_APPL) | 技术底座与业务应用完全分离 |
| **命名空间** | /SAP/* vs Z/Y/* | SAP 标准代码保护 |
| **传输系统** | CTS (Workbench vs Customizing) | 开发与配置分离 |
| **增强框架** | BAdI, Enhancement Spots | 标准代码与扩展代码隔离 |
| **包结构** | $SAP_* vs Z* | 层次化访问控制 |
| **客户端** | Client 000 vs 001 vs 100 | 配置数据与业务数据隔离 |
| **版本管理** | Support Packages | 独立的升级路径 |

### 8.3 关键要点

1. **技术底座组件和业务应用开发必须在不同的物理模块中实现**
   - 使用 Maven/Gradle 多模块项目结构
   - 平台层和业务层独立版本控制

2. **通过接口实现依赖倒置**
   - 平台层定义接口，业务层依赖接口
   - 业务层定义扩展接口，客户层实现扩展

3. **使用 SPI 机制实现可扩展性**
   - 类似 SAP 的 BAdI 机制
   - 支持多个实现并存
   - 支持优先级控制

4. **严格的命名空间控制**
   - SAP 使用 /SAP/* 保护标准代码
   - NextERP 使用 com.nexterp.* 保护标准代码

5. **版本兼容性管理**
   - API 版本通过 URL 路径隔离
   - DTO 版本通过包结构隔离
   - 接口版本通过 @since 注解标记

通过借鉴 SAP NetWeaver 的成熟隔离机制，NextERP 可以实现技术底座与业务应用的完全隔离，支持持续演进和客户定制。
