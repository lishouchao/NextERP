**模块**: Business Partner (业务伙伴)
**对标**: SAP S/4HANA BP
**版本**: 1.0
**更新日期**: 2026-03-16

---

## 1. 概述

### 1.1 设计理念

SAP S/4HANA 引入了统一的业务伙伴 (BP) 模型，NextERP 借鉴这一设计理念：

1. **统一主数据** - 一个业务伙伴可以同时是客户和供应商
2. **角色分离** - 通过角色控制不同业务场景的属性
3. **地址管理** - 支持多地址、多用途的灵活管理
4. **银行账户** - 支持多银行账户管理

### 1.2 与传统模型对比

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                     传统模型 vs BP统一模型                                   │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│   传统模型 (SAP ECC):                                                        │
│   ┌─────────────────────────────────────────────────────────────────────┐   │
│   │   客户主数据 (KNA1)           供应商主数据 (LFA1)                    │   │
│   │   ┌──────────────┐           ┌──────────────┐                       │   │
│   │   │ 客户编码      │           │ 供应商编码    │                       │   │
│   │   │ 客户名称      │           │ 供应商名称    │                       │   │
│   │   │ 地址信息      │           │ 地址信息      │  ← 数据重复          │   │
│   │   │ 银行信息      │           │ 银行信息      │                       │   │
│   │   └──────────────┘           └──────────────┘                       │   │
│   │        问题: 同一公司既买又卖时，需维护两套主数据                       │   │
│   └─────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
│   BP统一模型 (S/4HANA):                                                      │
│   ┌─────────────────────────────────────────────────────────────────────┐   │
│   │                    业务伙伴主数据 (BUT000)                           │   │
│   │                    ┌──────────────────┐                             │   │
│   │                    │ BP编码 | 名称     │                             │   │
│   │                    │ 地址   | 银行信息 │                             │   │
│   │                    └──────────────────┘                             │   │
│   │                           │                                          │   │
│   │              ┌────────────┴────────────┐                            │   │
│   │              ▼                         ▼                            │   │
│   │       ┌──────────────┐         ┌──────────────┐                     │   │
│   │       │ 客户角色     │         │ 供应商角色   │                     │   │
│   │       │ (ZCUSTOMER)  │         │ (ZVENDOR)    │                     │   │
│   │       │ 客户专属属性 │         │ 供应商专属   │                     │   │
│   │       └──────────────┘         └──────────────┘                     │   │
│   │        优势: 一个BP，多个角色，数据不重复                              │   │
│   └─────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘

## 2. 业务伙伴类型

### 2.1 类型分类

| 类型 | 代码 | 说明 | 必填字段 |
|------|------|------|----------|
| 个人 | P | 自然人 | 姓名、性别、出生日期 |
| 组织 | O | 法人实体 | 公司名、法律形式、税号 |
| 集团 | G | 集团公司 | 集团名、关联公司 |

### 2.2 类型属性

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                           业务伙伴类型属性                                   │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│   个人 (P):                                                                  │
│   ┌─────────────────────────────────────────────────────────────────────┐   │
│   │   必填: first_name, last_name, gender, birth_date                   │   │
│   │   可选: title (称谓)                                                 │   │
│   │   自动: name = first_name + ' ' + last_name                        │   │
│   └─────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
│   组织 (O):                                                                  │
│   ┌─────────────────────────────────────────────────────────────────────┐   │
│   │   必填: name (公司全称)                                              │   │
│   │   可选: name_2 (名称2), short_name (简称)                            │   │
│   │         legal_entity_type (法律形式)                                 │   │
│   │         incorporation_country (注册国家)                             │   │
│   │         tax_number (税号)                                            │   │
│   └─────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
│   集团 (G):                                                                  │
│   ┌─────────────────────────────────────────────────────────────────────┐   │
│   │   必填: name (集团名称)                                              │   │
│   │   关联: 子公司列表 (通过BP关系)                                       │   │
│   └─────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

## 3. 角色模型

### 3.1 角色类型

| 角色 | 代码 | 说明 | 触发业务 |
|------|------|------|----------|
| 客户 | ZCUSTOMER | 销售客户 | 销售订单、开票 |
| 供应商 | ZVENDOR | 采购供应商 | 采购订单、付款 |
| 工厂 | ZPLANT | 生产工厂 | 生产订单 |
| 个人 | ZPERSON | 个人BP | 个人业务 |
| 组织 | ZORGANIZATION | 组织BP | 组织业务 |

### 3.2 角色分配流程

### 4.1 地址类型

| 默认地址 | 01 | 主地址 | 基本信息、默认联系 |

┌─────────────────────────────────────────────────────────────────────────────┐
│                           信用管理流程                                       │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│   1. 信用额度设定                                                           │
│   ┌─────────────────────────────────────────────────────────────────────┐   │
│   │   BP级别: credit_limit (bp_business_partner)                        │   │
│   │   公司级别: credit_limit (bp_customer)                              │   │
│   │   信用组: credit_group (控制规则)                                    │   │
│   └─────────────────────────────────────────────────────────────────────┘   │
│                          │                                                  │
│                          ▼                                                  │
│   2. 信用检查                                                               │
│   ┌─────────────────────────────────────────────────────────────────────┐   │
│   │   信用占用 = 未清订单 + 未清发票 + 应收余额                          │   │
│   │                                                                       │   │
│   │   if 信用占用 > 信用额度:                                             │   │
│   │       触发信用冻结                                                    │   │
│   │       需要信用审批                                                    │   │
│   └─────────────────────────────────────────────────────────────────────┘   │
│                          │                                                  │
│                          ▼                                                  │
│   3. 信用状态                                                               │
│   ┌─────────────────────────────────────────────────────────────────────┐   │
│   │   01: 正常 (无风险)                                                   │   │
│   │   02: 警告 (接近额度)                                                 │   │
│   │   03: 冻结 (超额度)                                                   │   │
│   └─────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘

### 6.2 重复检查

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                           重复检查规则                                       │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│   检查维度:                                                                  │
│   ┌─────────────────────────────────────────────────────────────────────┐   │
│   │   1. 税号匹配 (tax_number)                                           │   │
│   │      完全匹配 → 提示重复                                              │   │
│   │                                                                       │   │
│   │   2. 名称相似度                                                       │   │
│   │      相似度 > 80% → 提示可能重复                                      │   │
│   │                                                                       │   │
│   │   3. 地址匹配                                                         │   │
│   │      相同地址 + 相同名称 → 提示重复                                   │   │
│   │                                                                       │   │
│   │   4. 银行账户匹配                                                     │   │
│   │      相同银行账号 → 提示重复                                          │   │
