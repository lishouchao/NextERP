# SAP ECC vs S/4HANA 数据库设计对比分析

## 概述

本文档对比分析 SAP ERP ECC 6.0 和 S/4HANA 两个版本在数据库设计上的核心差异。

## 架构层面差异

### 1. 数据库平台

| 特性 | ECC 6.0 | S/4HANA |
|------|---------|---------|
| 支持数据库 | AnyDB (Oracle, SQL Server, DB2, MaxDB) | 仅 SAP HANA |
| 存储方式 | 行存储 | 列存储 (HANA 优化) |
| 内存使用 | 磁盘为主 | 内存优先 |
| 压缩 | 有限 | 高度压缩 (10-100x) |
| 并行处理 | 有限 | 大规模并行 |

### 2. 表类型变化

| ECC 表类型 | S/4HANA 变化 |
|-----------|-------------|
| 透明表 | 保留，部分转为列存储 |
| 聚簇表 | **转换为透明表** |
| 池表 | **转换为透明表** |
| 视图 | 部分转为 CDS View |

### 3. 关键聚簇表转换

```
┌─────────────────────────────────────────────────────────────┐
│                    ECC 聚簇表 → S/4HANA 透明表               │
├─────────────────┬─────────────────┬─────────────────────────┤
│ ECC 聚簇表       │ S/4HANA 表       │ 说明                    │
├─────────────────┼─────────────────┼─────────────────────────┤
│ BSEG            │ BSEG            │ 会计凭证段（转为透明表）  │
│ KONV            │ PRCD_ELEMENTS   │ 条件项（拆分重构）        │
│ PCL1            │ PCL1 (透明)     │ HR 数据聚簇 1            │
│ PCL2            │ HRPY_* 系列     │ HR 薪酬数据（拆分）       │
│ CDCLS           │ CDCLS (透明)    │ 更改文档                 │
│ KOCLU           │ -               │ 成本控制聚簇（消除）      │
└─────────────────┴─────────────────┴─────────────────────────┘
```

#### 2.4 CDS Views 替代传统报表

```sql
-- ECC: 逻辑复杂的 ABAP 报表
REPORT ZHR_EMPLOYEE_LIST.
SELECT * FROM PA0001 WHERE ...
LOOP AT ...
  " 复杂的数据处理逻辑
ENDLOOP.

-- S/4HANA: 声明式 CDS View
@AbapCatalog.sqlViewName: 'I_EMPLOYEE'
define view I_Employee as select from PA0001
inner join PA0002 on ...
{
    key PERNR,
    FirstName,
    LastName,
    OrgUnit,
    Position,
    ...
}
```

### 3. CDS Views

```sql
-- S/4HANA CDS View 示例: 客户余额视图

@AbapCatalog.sqlViewName: 'I_CUSTBL'
@AccessControl.authorizationCheck: #CHECK
@EndUserText.label: 'Customer Balance'
@VDM.viewType: #CONSUMPTION

define view I_CustomerBalance
    as select from ACDOCA
{
    @EndUserText.label: 'Customer'
    key RCUSTOMER as Customer,

    @EndUserText.label: 'Company Code'
    key RBUKRS as CompanyCode,

    @EndUserText.label: 'Fiscal Year'
    key RYEAR as FiscalYear,

    @EndUserText.label: 'Balance'
    sum(CASE WHEN RDEBCRE = '1' THEN HSL ELSE -HSL END)
        as BalanceInCompanyCodeCurrency
}
where
    RCUSTOMER <> ''
group by
    RCUSTOMER, RBUKRS, RYEAR
```

## 迁移影响分析

### 1. 代码适配需求

| 适配类型 | 工作量 | 说明 |
|---------|--------|------|
| 聚簇表访问 | 高 | IMPORT/EXPORT → SELECT |
| 聚合表引用 | 高 | 改用 CDS Views |
| KONV 访问 | 中 | 改用 PRCD_ELEMENTS |
| BP 模型 | 中 | KNA1/LFA1 → BUT000 |
| CDS 集成 | 中 | 重写报表逻辑 |

### 2. 自定义代码扫描

```abap

" 3. KONV 访问
```

## 总结

### 关键变化

1. **Universal Journal (ACDOCA)** - 财务数据统一
2. **聚簇表消除** - 全部转为透明表
3. **聚合表消除** - 实时计算替代
4. **BP 模型强制** - 客户/供应商统一
5. **CDS Views** - 数据访问层标准化
6. **HANA 优化** - 列存储、压缩、并行

### 迁移建议

1. 使用 SAP Readiness Check 评估
2. 重点关注自定义代码
3. 测试 KONV → PRCD_ELEMENTS 迁移
4. 规划 BP 模型迁移
5. 考虑 Fiori 应用替代经典事务
